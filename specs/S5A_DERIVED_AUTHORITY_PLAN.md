### Proposed engine record and transaction boundary

Recommend a small versioned **electrical identity source family** under substrate
ownership, separate from recomputable connectivity cache. Candidate layout:
`.datum/electrical-identities/<record-id>.json`, one typed record per owner,
with schema version, stable ID and object revision. This is a proposal, not an
existing path or accepted new source-shard kind. Integrate with resolver shard
discovery/schema validation, DomainObject inventory, model revision and normal
staging/journal/replay; do not add a second resolver or identity sidecar authority.

| Proposed record | Minimum source fields / derived fields excluded |
| --- | --- |
| NetIdentity | Persisted NetId, object revision, anchor reference (label, wire endpoint index, pin or explicit source); anchor includes occurrence context when needed. Display attribute and source provenance are explicit. No cached current membership as source authority. |
| BusIdentity | Persisted BusId, object revision and anchor authored Bus occurrence. Geometry/member-Net results are derived; equal name/member list does not create an identity binding. |
| Net implementation binding | Relationship ID/revision, canonical NetId, board ID + existing board Net ID/revision, binding intent and validated basis refs (ComponentInstance, pinned PinPadMap, placed pin/pad where applicable). Reuse ImplementedBy ownership; distinguish BoardOnly/SchematicOnly intent from unresolved/pending mapping. No new competing component join or confidence-from-name fallback. |
| Bus hierarchy binding | Stable binding ID/revision, semantic BusId, exact authored Bus occurrences and typed parent/child interface refs. Resolved scalar member-Net relations are results, not implicit equivalence between buses sharing a display name. |

One guarded parametric identity-record create/set/delete family is proposed,
using existing native-write BatchComposer → canonical commit/staging/journal →
inverse/replay/schema checks. No per-class public tool explosion. Identity and
binding maintenance must be included in the **same** authored topology-changing
batch before commit; no second transaction after a successful wire/label edit.
All writers get the same engine preflight. Avoid modifying unrelated authoring
families; only edits that change these identities/bindings need this integration.

Surviving anchors keep NetId. Proposed generalization of the existing binary
split law: anchor-containing group keeps ID, each orphan group receives one
persisted ID in the authored batch; absent surviving anchor, choose a deterministic
replacement source ref and record it. Proposed multiway merge generalizes the
existing lowest-NetId survivor; record merged-away IDs/binding updates in that
same transaction. Order groups/refs canonically; record allocated UUIDs in the
batch so replay never generates new ones. Undo/replay restores source identity
history; consumer selection does not resurrect dropped identities. Display
rename and unchanged-group edits allocate zero IDs. Cache-only recomputation
may refresh derived anchor resolution but cannot persist new identity/transitions.

Old projects must not be “fixed” by a read. Proposed adoption is an explicit
reviewable native prepared batch over the expected model revision, preserving
all existing authored IDs and board Net references. Reuse an existing authoritative
Net ID where its ownership/binding is proved; allocate only absent logical
identities. ImportMap/source provenance proves adoption, not equal names or
legacy summary UUIDs. Read-only projects lacking records return authority
unavailable plus exact affected refs; adoption is not S5A selection behavior.
Source schema/replay coverage must exist before any adoption builder is exposed.
No automatic startup adoption, import campaign or writer-lock redesign is proposed.

instance-path context, not a single union node for the child root sheet.

route. Reuse board geometry and existing copper graph predicates only where exact
