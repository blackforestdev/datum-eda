## One shared hover dependency

Introduce a renderer-owned `BoardHoverDependency` classification derived from
actual immutable board pad membership and selection semantics. Do not classify
by object-ID spelling and do not let an editor supply a cold/warm flag.

- Selection suppressing hover yields Disabled. No pad match yields None;
  a matching pad yields its source-bound identity. Ambiguous or unavailable
  membership yields Unknown and preserves the current full fallback.
- Use the same classification for the retained-content cache key and prepared
  pointer gate. Remove all-board-hover keying and `Region` identity as the
  definition of a material change. Equal non-pad dependencies permit immediate
  pointer/ring refresh while retaining the world, projection and prefix key.
- Preserve cold handling on entering/leaving/changing a real pad dependency,
  including legacy copper/paste/mask emphasis and hovered net labels. Preserve
  selection, source replacement, camera/chrome and target invalidation.
- For pointer calls, source-bound pad membership is immutable metadata of the
  retained scene's existing hit index: one bit per region, generated by actual
  scene-pad ID equality during preparation. Resolve the incoming hover through
  that index, then read its bit. No new editor classification path or unversioned
  board source enters `PointerUpdate`. Unknown hit IDs retain full fallback.
- Charge bitset payload, allocation/Arc headers and construction scratch through
  the existing document CPU accounting. Include it in retained history and weak
  geometry lifetime observations, deduplicated across shared clones and counted
  while frame plans keep it live. The64MiB document/history and six-entry limits
  do not increase. Optional metadata admission failure means Unknown/full work,
  never "no pad". A missing prepared generation cannot accept a stale hint.

For the measured non-pad transitions this removes whole-world replacement,
world upload continuation, prefix rebuild and full A-to-B copy. It deliberately
retains genuine pad-material reconstruction. It is not a workload-specific ID
whitelist, semantic removal or replacement of the shared source contract.

## One shared disjoint painter clip

Have the shared damage owner normalize presented/desired support into an exact
union of disjoint integer rectangles, still bounded by32. Use fallible fixed
inline construction: split overlaps, merge compatible adjacent rectangles, and
fall back to the existing full graph if the representation cannot fit. Do not
replace the union with one large crosshair bounding box or raise a cap.

Use that same immutable union for sample restoration, damage masks and suffix
clips. Keep one8×working attachment and one render pass for all suffix regions.
For each disjoint region traverse the existing ordered suffix painter once;
every draw uses intersection of its original clip, region and target extent.
An empty intersection issues no draw. Each pixel therefore sees the original
painter order exactly once, even when old/new crosshair and hover bounds overlap.
The current shared shader predicate remains as a correctness guard.

`gpu_frame_painter.rs`, `gpu_console.rs` and `terminal_graphics.rs` must consume
this clip instead of overwriting it. Workspace/foreground/menu glyph calls inherit
the intersected scissor; glyph-instance clipping and derivative sampling stay
unchanged. Adapt any other current suffix consumer found by the all-call-site
scissor review before enabling the path. Full/cold/capture/dialog encoding keeps
the same common painter and an unrestricted clip. No duplicate editor painter.

Retire fragment-discard-only damage execution for eligible warm frames and
unconditional full painter scissors on that path. Do not add one render pass or
resolve per rectangle. Full-target resolve remains; this proposal does not
replace it with a numerically different shader resolve or lower antialiasing.
