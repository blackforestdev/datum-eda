## Minimal shared contract

One render-owned RenderSession per native host owns derived current/prepared composition, typed pending render changes, composition/interaction generations, retained-resource references, optional prefix A + frame B and their lifetime/accounting. Migrate existing retained history and admission implementation into the shared boundary; preserve existing document charging/sharing, limits, rollback and retirement. Do not make per-host sessions duplicate a world's storage or replace working history policy with another cache.

Editors submit immutable versioned RenderInput with document/scene handles and revisions, ordered pane descriptors (identity, camera, layout, style/layers, grid policy), interaction state, text/terminal/menu snapshots and host configuration. Native domain inputs remain app-owned: canonical design, terminal core/PTY, user camera values, input semantics, focus/IME, and window handles. Renderer owns derived projections and grid-LOD render dependencies, not editor command semantics.

Use a small typed RenderChange family: Interaction, Composition, PresentationConfiguration, LifecycleInvalidated, and Exposure. Any nonpointer/suffix-only content update initially conservatively becomes Composition under r1. Merge pending changes monotonically: Interaction cannot overwrite stronger Composition/configuration invalidation. Unknown/unsupported change invalidates fully. External change tags are hints plus explicit versions, not permission to ignore changed source identities. Validate all mutations through the same owner.

RenderSession::update(input, change) returns a render-demand token/epoch, not a winit redraw. Existing coordinator remains the sole request_redraw and host scheduling authority. RenderSession::prepare(request) yields a coherent immutable PreparedFrame lease (or explicit Deferred/Refused), including source/host/device/configuration/composition/interaction epochs and the relevant terminal snapshot/damage lease. Native and capture adapters both use this path; input/hit queries obtain a read-only scene projection without GPU acquisition or a separate preparation authority.

RenderSession::encode(frame, target_adapter) returns typed UploadContinuation, Deferred, or Submitted receipt. Submission is not presentation. Platform adapter presents through SurfaceTransaction and returns PresentSuccess/Failure for the same host/device/configuration/attempt/frame receipt. Session publishes reusable prefix generation and presented hit/layout snapshot only for the matching success; failure invalidates cache, preserves pending changes and terminal damage. Duplicate/old/foreign receipts cannot clear current changes. GPU completion separately retires submission resource references through existing QueueOwner; present does not mean GPU completion. Captures have explicit offscreen completion semantics and must not publish native displayed-hit state.

Keep receipt plumbing narrow: join the existing coordinator and surface receipts to renderer frame identity; do not invent a second queue scheduler, OS lifecycle state machine, or second authoritative damage counter in an app wrapper.

## Concrete retirements / retained paths

1. Retire app-owned nullable PreparedScene rebuild decisions and scene_dirty-as-render-cache authority from interaction_refresh, runtime_terminal_render, runtime_present and capture. Transitional scene_dirty may only be a derived adapter signal until callers migrate; do not retain two writable authorities.
2. Retire direct app calls to prepared.set_schematic_camera/set_surface_camera/set_surface_grid_lod and writable prepared fields. Normalize complete pane descriptors before immutable preparation. Preserve independent pane cameras and LOD hysteresis; avoid allocating/drawing a scene per pane.
3. Retire raw render_with_acquisition(prepared, retained, schematic_retained, width, height, ...) as an editor-facing composition API after all native/capture consumers move to session receipts. Internal narrow GPU encoding and late-acquisition target adapters remain legitimate.
4. Normalize legacy inputs to explicit pane descriptors at an ingress adapter, then delete the GPU encoder's empty-composition fallback world/grid recipes. Inventory remaining capture/fixture/no-pane consumers before deletion. A genuine empty composition stays empty. Dialog profile remains a legitimate single-pass graph without world or prefix cache.
5. Reference/full-frame fallback and prefix-copy mode use the same normalized ordered prefix/suffix encoder. Full redraw remains necessary on invalidation/admission refusal; retaining the old independent compositor as rollback/reference policy would preserve the architecture split.
6. Keep NativeFrameCoordinator, NativeRenderTarget, SurfaceTransaction and QueueOwner, their fairness/backoff/configure/acquire/present/platform notifications and completion semantics. Unify only duplicated adapter orchestration/publication, not their distinct responsibilities.

## Copy mechanism and proof pitfalls

The full equal-format 8x prefix A-to-B copy remains sound as a candidate: stored prefix samples then unchanged suffix once and final resolve. Warm eligible pointer frames execute no prefix world/grid/panel draws. Exact pixels, resource admission, key invalidation, no new world uploads and lifetime proof remain required; sample preservation is an argument, not a GPU proof result.

Review gates should prove retirement, not just a new API name: every production consumer enters shared preparation; no app direct PreparedScene mutation; default encoder has one world traversal policy; pointer + composition changes coalesced in either order rebuild; upload-only/acquire/present failure never publishes cache; overlapping in-flight change retains latest damage; capture cannot acknowledge native damage; same-length scene replacement and cloned snapshots cannot reuse old prefix; empty/no-board/dialog layouts never resurrect legacy world. Reuse historical tests at unchanged scope, run new proof only after owner authorization.

Treat terminal snapshots as leases with explicit acceptance/rollback. Do not lose consumed dirty rows when preparation succeeds but encoding/acquisition/presentation fails, or duplicate PTY authority inside RenderSession. Preserve last successfully presented hit map during dirty/failed frames; immutable geometry ownership must not regress the existing take-once publication behavior or silently duplicate unaccounted buffers.

Migrating camera stores, terminal services, editor selection semantics, all raw input dispatch or event-loop scheduling is unnecessary scope. Migrate their derived-render handoff, not their product authority. Retained-history relocation should preserve existing algorithms and document limits; no speculative cache redesign.
