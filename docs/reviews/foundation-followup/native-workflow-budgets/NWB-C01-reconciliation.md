## §B — The two PM051 traps this lane holds hardest (stated before any fixture)
1. **Fixture counts ARE PM051 numbers.** An "object count" or "realistic scale population" is a figure. Every population size here carries a stated **basis**:
   - **Minimal-correctness fixtures:** basis = **minimality** — the smallest object set that exercises exactly the behavior under test. This is a defensible, non-arbitrary basis (it is *not* a realism claim); the count is derived from the correctness scenario, not invented.
   - **Realistic-scale populations:** basis = **representativeness derived from something real** — governed fixtures, real NATIVE-design statistics, or documented workflow scale. Where no such native basis yet exists, the exact N is left **UNDECIDED** with its basis-source requirement stated (a constraint carried to NWB-C02/owner), **never** an invented round number labelled "realistic."
   - Minimal-correctness fixtures are kept DISTINCT from realistic-scale populations throughout; **a scale population is a fixture-size statement, not a performance budget** (no latency/throughput target is smuggled into a count).
2. **Native means native (PM011).** Every fixture is NATIVELY AUTHORED through the native path (typed Operations through the one commit path). **No imported-format fixture counts as native authoring** — in particular the KiCad `datum-test` regression fixture (import-frozen) is explicitly NOT usable as a native-authoring or native-scale fixture here; leaning on it would be a finding. Import-derived data is excluded from this lane's fixtures.

## §D — Per-fixture specification schema (the seven governed attributes)
Every fixture below specifies all seven bound attributes so a later measurement is reproducible:
(1) **native identities** (stable ObjectId per PM001; NetId per PM053 where electrical) — authored natively;
(2) **object counts + topology** (count with its §B basis; topology = concrete connectivity, not hand-waved);
(3) **coordinates** (canonical signed-integer nm, PUBLISH §5.1 — deterministic, no floating/ambiguous placement);
(4) **project/settings state** (the exact Project + settings each fixture assumes — PM040 units, no ambient dependence);
(5) **journal baseline** (the starting transaction tip / revision baseline, PM001/PM000D — so commit timing measures from a known point);
(6) **reset method** (deterministic reset to baseline between runs, no residue);
(7) **expected reopen result** (the deterministic resolved DesignModel / revisions after load — PM000D deterministic reopen; incoherent load opens in recovery, never silent partial).
