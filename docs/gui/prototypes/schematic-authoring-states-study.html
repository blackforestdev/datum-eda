S-JWire edit handle states — end, bend and span over the logical contact graph ○ TARGET · not delivered◐ OWNER CHOICE · S05◇ SYNTHETIC

Candidate presentation for the delivered shared wire-editing verbs (18d59b9a): the engine already edits wire ends, nodes and spans through the one shared Move with canonical batch, raw identity, locks and history, but no handle glyph is rendered yet — this family is the visual contract for them. Vocabulary extends frame E1 (square = vertex, ring = snap target): □ end handle on a physical wire end, ◇ bend handle on an interior vertex, the span is the segment itself, and ◉ node is a junction-owned shared contact whose drag preserves every connection. Shape distinguishes them; colour is redundant. Handles render for the selected wire only and share the one acquisition envelope; drawn pixel sizes are placeholders (Design Book tokens govern). Datum laws unchanged: Ctrl is subtractive selection, Escape cancels the gesture first, Space pan is untouched, commits are one canonical journal entry each. Altium is comparator only — no key, default or glyph is copied.

S-KNumeric placement form — exact coordinates for a captured handle ○ TARGET · not delivered◐ OWNER CHOICE · S05◇ SYNTHETIC

The canonical move verb already accepts exact integer-nm absolute anchors (● CURRENT · bounded at its recorded scope); the ordinary manual form is undelivered (audit wire_precise_xy_offset). This is the one shared form, configured by the captured handle — wire end here, any Move subject by the same shape — not a wire-only editor. Values display in Project Working Units captured when the edit begins (PM040); a mid-edit units change never retargets an open form. The source i64 nm is the authority: an untouched field keeps its exact value, and display rounding never writes back. The opener is a visible Coordinates… button in the captured Move prompt — no new global hotkey. Cancel or Escape closes the form, preserves the prior Move preview and writes nothing; the next Escape cancels the Move itself. Tab / Shift+Tab traverse the fields through the existing shared single-line editor, which also owns text, caret and clipboard behavior; mouse Apply validates and submits the same captured plan as a pointer release. Plain arrow keys in the captured gesture are the shared Move displacement input (K4) — one current-grid step per press, no separate nudge panel, speed modifier or extra hotkey; Space pan is untouched.

S-PPCB reference / value change review — schematic Reference and display Value edits read against the existing board counterpart ○ TARGET · not delivered◇ SYNTHETIC

Candidate presentation for reviewing Reference and display Value edits already authored in the schematic against the board counterpart that an earlier transfer created. Native proof is PENDING — nothing in this family claims a delivered surface, runtime behaviour or a product PASS. Entry is the retained root-schematic transfer review: its existing card carries the trigger (P1), and pressing it closes the card and opens the existing shared inline Proposal review in the same captured root context — no pane switch and no new board-side entrypoint; the board counterpart appears only as read-only data inside the review. The payload rides that inline Proposal review unchanged: Tab applies only while the review is complete, current and ready; Esc always dismisses; pending (“Preparing Proposal…”) and refusal presentation are the shared semantics, not new rules. Opening the review inspects the design source to prepare the immutable old/new diff; nothing in the design changes before explicit acceptance. Applying submits one proposal that updates the board's Reference and display Value text only — placement, pads, nets, routes and the component's pinned physical choice stay exactly as they are. Out of scope here: library revision, footprint or map selection, topology, component addition or removal, simulation and general engineering-change flows; the initial transfer of a component to the board remains its own separate review. Every part, footprint, reference and value drawn is an illustrative synthetic first-party example.
