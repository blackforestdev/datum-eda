What these actions may and may not do. New Folder makes one folder inside the current Location; Rename changes one folder or file name inside its own folder. Nothing is deleted, overwritten, moved to another folder, or renamed through a link, and no Project or Library is renamed or relocated this way. Both actions refuse to write inside a Datum Project’s or open Library’s own storage, and refuse to create Datum’s own backing storage where Datum manages it — the reserved .datum folder and a Project’s or Library’s managed revision, pool and schema stores. An ordinary folder that merely happens to be called revision, pool or schema elsewhere is not affected. NPD-C09 — LOCATION SUGGESTIONS AND TAB COMPLETION · CURRENT ADDENDUM
Current C09 visual and interaction target under the owner’s path-assistance request (PM063 “Location suggestions and completion”) and the appointed manager’s recorded disposition; no native implementation, runtime, production or HUMAN acceptance is claimed. While you type the last folder name in Location, New and Open show matching folders in the same inline list — no extra search box, dialog or sidebar — and Tab can finish the name. Location stays exactly what you typed until you accept a suggestion.
How it behaves. While you are typing the text after the last “/”, Datum treats it as a search: it reads the folder before it and lists its folders whose names contain what you typed — even when what you typed already names an existing folder, which is entered only when you accept it, press Enter, or type a trailing “/”. The root “/”, “~” and “.”/“..” keep their usual meaning instead of becoming searches. Matching ignores case (for matching and order only), lists names that start with the text first, and always shows names spelled exactly as on disk, dot-folders included. The always-visible list switches to these suggestions (Browse… stays); a header line names the folder being searched and what is matched, so it cannot be mistaken for an ordinary listing. A partial name or a name with no matches is a draft, and stays neutral: “no matching folders” is a plain status line, not a red error. A real problem — a folder that cannot be read, an invalid name — is still described as it is, and an explicit navigation, Create or Open that fails reports the attempted path and the reason. Suggestions only help you type — they never change the candidate, never feed Create or Open, and never enable New Folder, Rename or the project.json shortcut, which need an ordinary listing of an exact folder. Create and Open still check exactly what Location says; they never fall back to the folder being searched or to the first match, and a Create or Open refusal appears only after you press Create or Open (P-E); a folder that cannot be read is still described as soon as it is found.

What the existing terminal panel shows before and after a Project is created or opened. It reuses the existing tab strip (44 high, tabs up to 152 wide with their 28-wide close, the + button, the lifecycle chip) and adds one thing: a context label in the strip’s trailing area naming the selected session’s binding and directory. Nothing is drawn in the terminal cells, and no sidebar, welcome, dialog or prompt is added. The retired terminal-study remains historical and is not this target.
Rules shown below. The panel keeps its visibility, height and maximized/restored state through New and Open. Successful New or Open adds and selects the prepared terminal started in the Project’s root with that Project’s context; every existing session — Home, an AI agent, another Project — keeps its process, directory, environment and scrollback. No cd, restart, rebinding or migration question. Selecting the Project tab does not take keyboard focus from the editor (hollow cursor = no keyboard focus). Cancel, refusal or stale preparation change nothing. Tab label: by default “Home” for an independent session started in your home folder, or the Project name for a Project session; a name you gave the tab, or a useful program title such as “codex”, is kept. Context label (selected session only, separate from the tab label): “Independent shell” or “Project: <name>”, then the directory — the shell’s reported current directory when valid, otherwise “Started in <path>”. A directory never means a binding: an independent shell standing in a Project folder is still “Independent shell”. The context label takes the place of the routine shortcut hint, reads in full whenever there is room, and is the first thing to shorten when there is not (path before binding): tabs, close and + controls and any lifecycle or error chip are never displaced.

If you had closed the panel, New and Open leave it closed. As today, closing hides only the terminal cells and gives their room to the editor: the tab strip stays, with every tab, its close button, the + button and the context label. The prepared Project tab is the selected one — drawn without the open-panel fill and accent, but in full-strength text and announced “selected, panel closed” — and the context label names it. Nothing is added to the status bar. The sessions keep running. Reopening the usual way (for example clicking a tab) brings the cells back at the previous height with that Project session showing.
TH-F · maximized or restored. If the panel was maximized before New or Open it is still maximized afterwards, showing the selected Project session; if it was restored, it keeps its restored height. This is the existing panel geometry carried across the Project change — no new layout, surface or control. The same rules hold at the 620 minimum (TH-D).
