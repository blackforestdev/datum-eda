Datum · Library Surfaces Study — per-kind editors, process and models

◐ OPEN CANDIDATE · SURFACE-S04 · not approved, not implemented, not product-ratified

Detail and manual editing for the eight Pool kinds, body / land / padstack process truth, and model attachments (frames L-B, L-B1–L-B8, L-D, L-E). This page is part of a three-page candidate study; the index, frame legend and frame → clause map are in library-surfaces-study.html. Nothing here selects a presentation, a policy, a threshold or an implementation successor; the owner's SURFACE-S05 disposition is still ahead.

Every pool, object, manufacturer, MPN, identifier, hash, dimension and value drawn here is an illustrative synthetic first-party example. None is an approved library asset, a real manufacturer part, a standards-derived number, a real digest or a production seed. Where a number appears it is a made-up example that shows where a value is displayed and compared, not what it should be. Pixel sizes and font stacks are mockup placeholders; tokens govern.

Pad shape note. Current native library apertures are Circle and Rect. Every land in this study is therefore drawn as a plain square-cornered Rect. The Rendering Book's rounded-rectangle pad direction is not materialized by a native aperture today; a rounded rectangle is shown only where it is explicitly marked unsupported (L-B7, L-D). That difference is shown, not resolved.

L-BEight per-kind frames — each with detail AND manual editing ○ TARGET · not delivered◐ OWNER CHOICE · S05 — editor presentation◇ SYNTHETIC

Every kind shows its detail and a manual create / edit surface, and every card carries the same three-state strip: editing (a local preview — nothing authored), review (the listed changes), then Commit or Cancel. The current state is the heavier, bold chip. Commit goes through the existing library authoring builders as one typed transaction on the canonical commit / journal path, followed by resolver refresh; canonical undo / redo and project Save / reopen apply. No editor here has its own writer. Cancel leaves no authored delta and no history entry. Clone creates a new identity; rename is not identity replacement. Where an object is bound to placed components, the commit control becomes Create proposal — the existing boundary. Controls with no backed command are dashed and marked ∅. The bottom strip of each card quotes the reusable seam and remaining delivery from the Product contract; a seam is not GUI delivery.

L-DPackage versus Footprint versus Padstack — copper, mask, paste, drill ○ TARGET · not delivered◇ SYNTHETIC

Three objects, three questions: the Package is the physical body and its eight terminals; the Footprint is the board land pattern with its eight lands; the Padstack is the per-layer pad definition a Footprint pad points at. Copper, mask and paste are separately inspectable by pad and layer with their actual geometry, policy and derivation basis. Inherit, a zero offset, or looking like the neighbouring pads does not establish correctness, and no universal expansion or reduction is applied or suggested. Where a layer's geometry is not resolved, no geometry is drawn for it.

L-EModels — detail, attach, edit metadata, detach, preview; refusal and cancel ○ TARGET · not delivered◇ SYNTHETIC

Models are governed attachments on a library target, not a Pool kind. Inspection never executes a simulator and never decrypts vendor content. Attach, detach and metadata edits go through the same library authoring / proposal path and show target, role, format, actual content hash and transform before committing. Part behavioural attachment slices and path-only Package 3D references exist today; that is not complete governed behaviour across every target. Every file name, source and hash below is a made-up example — the hash strings are deliberately not valid digests — and nothing here is evidence that any real provider's model was read, validated or converted.
