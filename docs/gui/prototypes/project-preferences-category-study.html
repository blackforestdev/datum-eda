P-C · lossless editing — rounded display is never canonical input
What happens between viewing a value and committing one
Unfocusedthe value may be rounded for display to the resolved precisionwhat you read is a projection
On focusthe edit buffer is regenerated from the exact canonical value, never from the rounded display textadditional exact digits may appear; geometry does not change
Focus then blura no-op — no parse, no compare, no journal entrysame for Enter or navigating away without a semantic edit
Escapecancels the edit and restores the canonical valuethe buffer is discarded, nothing is written
A real editparses once, compares canonical values, and journals only an actual changere-entering the same value commits nothing
Nevergeometry is not rescaled, rounded or rewritten by any of thisshards stay byte-identical
Why this rule exists. With rounded display and immediate commits, reading a value then tabbing through it could otherwise write the rounded text back as though the user had typed it — silently destroying precision. Regenerating the buffer from canonical truth on focus, and journaling only a real comparison difference, makes viewing and traversing a value provably free of side effects.

Ordering rationale. Identity first, then the two things that govern how every number and drawing reads (Units, Drafting Standard), then the policy layer (Revision, currently deferred under PM-038), then what the project enforces and consumes (Rules, Library), then what it emits (Output, Publish), then who may act (Team). Schematic and Board sit last and dimmed because their project-scoped content is thin today — one schematic descriptor exists, and the 13 pcb descriptors are machine Presentation, not project policy.
Nine high-confidence, two provisional. The dimmed pair are drawn so their placement is settled now rather than argued later, but neither has enough project-owned content to justify a populated pane yet.
